Story 5.6, the admin map pane

Decisions tested before the ticket is refined. 2026-10-06.

Outcome

The five decisions proposed for the map pane held. Two changed shape under pressure: the "gold only with a position" rule moved out of shared code into the admin, and the refit stays a plain remount.

Locked

AGold pin 1 and the dashed path only with a stored position. With none: numbered card-coloured pins, no path, no marker.

Rejected: never gold, because the admin reads a cluster; always gold, as on the Carte.

EThe rule lives in the admin; the only shared change is an optional recentre. mapPins and round-map.ts stay untouched.

Rejected: an optional argument on mapPins (a second home for the rule).

BStatic import of RoundMap. It is already its own precached 4 KB chunk and Leaflet is already in the admin chunk. The build confirms it.
DControls on top, then the map, then the list on a phone; two panes with a sticky map from md.

Rejected: list first; a Liste/Carte toggle.

CMap keyed by agent, mounted for any loaded round, with no pins it shows the default view or the position.

Rejected: a refit prop on RoundMap; hiding the pane; an in-pane message.

FitThe map keeps fitting to the pins and the position together. No new prop.

Weak points that survived

  • With a position, gold pin 1 can be hours old; only "Position du …" says so.
  • On a 390×844 phone the list starts below the fold.
  • A remount re-requests OSM tiles on every agent change.
  • An empty-looking map beside "Aucun arrêt…" is the common state once a round is done.
  • A reading far from the stops shrinks them until the admin zooms. Not seen yet; revisit on the 5.7 seeded Flow 3 run.
