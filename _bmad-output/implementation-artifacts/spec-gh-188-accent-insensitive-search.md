## Intent

**Problem:** `GET /api/admin/prospects?q=` (and the CSV export, which shares the filter) matches `name` with SQLite `LIKE`, which folds ASCII case only. As a result, `?q=cafe` misses "Café du Port" and `?q=CAFÉ` misses "café". That is a real gap in a French-language app.

**Approach:** Store a folded copy of the name in a new nullable column, `prospects.name_search`. A pure shared function, `foldForSearch`, lowercases, applies NFKD, strips combining accents and spells out œ/æ. Every Worker write of `name` also writes it. `q` is folded the same way and matched against that column. Rows whose `name_search` is still null keep today's match.

**Decision (owner, 2026-10-11) — backfill:** the migration sets `name_search = lower(name)` for pure printable-ASCII names (`name NOT GLOB '*[^ -~]*'`), exact because the fold equals `lower()` there; the daily cron drains the remaining null rows through `foldForSearch`, `RETENTION_BATCH`-sized per run, which also catches rows the old Worker writes during the deploy window. Spec kept whole at ~1,950 tokens (owner).

## Boundaries & Constraints

**Always:** Expand-only migration that the deployed Worker survives: the column is nullable and has no constraint. The needle stays bound and escaped as today (`!` escape). One filter is shared by the list and the export. `foldForSearch` lives in `src/shared` (pure). A new ADR records the stored derived column and its fold, because changing the fold later means re-folding every row (ADR-0024).

**Never:** No index on `name_search`. A `%needle%` cannot use one (free-tier-budget.md already says so), so it would only cost writes. Don't match against `dedupe_key`. Don't change `normalize()` or any dedupe key. Don't add `q` to the visits feed. Don't add a server-gaps row: epic #174 is closed.

## Design Notes

The issue asks for "its own index". It isn't needed: a leading-wildcard `LIKE` can't seek an index, as `docs/free-tier-budget.md` already records. The scan stays as it is today.

The fold strips only the Combining Diacritical Marks block, not `\p{Diacritic}` (which includes ASCII `^` and `` ` ``) or `\p{M}` (Indic vowel signs). That keeps it identical to `lower()` on ASCII and leaves other scripts intact.
