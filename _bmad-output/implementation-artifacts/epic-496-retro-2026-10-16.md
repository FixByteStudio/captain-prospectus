### Diff-scope review: Worker and shared

**F1. `writeTournees` can fail a sync after its visits are stored.** *Confirmed.* Fix now.
- `src/worker/routes/agent.ts:270` calls `writeTournees` with no guard, between the visit insert (step 2) and the response. The position write right below it (`:275-282`) has its own try/catch for exactly this reason (ADR-0028).
- Any throw returns a 500 with no `accepted`. Examples: a D1 error on one of the sequential statements, or an FK race on a stop.
  - The visits are already in D1, so nothing is lost, but the phone keeps them in the outbox and resends.
  - A persistent throw makes every later sync fail the same way, and the agent sees « non envoyées » for good.
- **Lesson:** when a story adds a write to the sync, its spec says what a failure of that write does to the visits' acknowledgement. ADR-0028 did this for the position; #498's spec did not.

**F2. The first tournée to arrive wins, not the first swipe.** *Confirmed* in source and by run 4. Both the adversarial and edge-case lenses found it independently.
- `src/worker/tournee.ts:50-53`: `onConflictDoNothing` on the unique (agent, day).
- Phone A swipes offline at 07:50 and walks its numbers. Phone B swipes at 08:30 and syncs first. On reconnect, A's tournée and stops are accepted and dropped, and A adopts B's numbering.
- The visits A recorded are unaffected (they carry no tournée id), but A's Tournée, Carte and Carnet numbers change mid-day.
- **Disposition:** fix as a story (action 6). The owner decided on 2026-10-16 that the earliest swipe wins, so the server must derive the winner from `min(client_started_at)` rather than from arrival order.

**F3. Nothing stops two stops from sharing a number.** *Confirmed.*
- `src/worker/tournee.ts:96-135` reads the tournée's numbers, filters in memory, then inserts. `src/worker/db/schema.ts:207-208` has unique (tournée, prospect) but no unique (tournée, number).
- Two concurrent syncs of one agent can both pass the check. Sequential syncs are handled (run 8b: both accepted, only the first stored).
- Raised three times and left open:
  - CodeRabbit flagged it on PR #517 at `tournee.ts:128` (Major, "Enforce number uniqueness at the database boundary"), with no reply.
  - PR #517's body offered it: "Say if you want it."
  - The #502 session left it for the owner.
- **Disposition:** defer to a story (action 3). The data stage is disposable, so the index is one migration with no backfill.

**F4. A stop whose prospect never arrives waits forever.** *Confirmed.* Defer (action 3).
- `src/worker/tournee.ts:88-90` holds such a stop out of `accepted` with no bound. Visits in the same situation are quarantined as `unknown_prospect` and acknowledged (ADR-0022).
- Causes: a phone restored against a wiped database, or a stale client id. Such stops are resent on every sync, and enough of them fill the 250-stop slice.

**F5. A stop naming a tournée the server does not hold for this agent is accepted and dropped.** *Confirmed.* Accept as designed and pin it with a server test.
- `src/worker/tournee.ts:56-67`, `:144`. The comment says this is meant for a tournée that lost its day.
- It also catches "not yet sent". Only the client's filter prevents that (`src/client/field/sync.ts:150-165`), and no server test pins the behaviour.

**F6. The Visites live feed can skip door-days when a poll is truncated.** *Confirmed in source, not run.* Fix now.
- `src/worker/door-days.ts:176-190` reads `received_at > since`, newest first, then cuts at `limit`.
- The client advances `since` to the newest row it holds (`src/client/admin/queries.ts:604-611`) and records `truncated` only on the seed page.
- A tab asleep through more than `limit` arrivals never fetches the cut rows. Rows tied on `received_at` at the cut are lost the same way.
- CodeRabbit flagged `door-days.ts:185` on PR #524 (Minor), with no reply; I did not re-read its text. The repaired-orphan case is already #528.

**F7. The duplicates screen counts raw visits.** *Confirmed.* Fix now (action 2).
- `src/worker/routes/admin.ts:1262-1274` uses `count()` over `visits` for `aVisits` and `bVisits`, while ADR-0036:182 says every admin number uses one unit.
- The owner decided on 2026-10-16 that it counts door-days, like every other admin figure.

**F8. The stop-number rule is written twice.** *Confirmed.* Fix now.
- `src/shared/schemas.ts:625` (`tourneeStopNumberSchema`) and `:697` (the same `z.int().check(z.positive(), z.lte(TOURNEE_STOP_NUMBER_MAX))` inline).
- If the two drift, the request accepts numbers that the response schema rejects, and the phone treats the whole sync as untrusted.

**F10. Worker tests fail in the hour after Brussels midnight.** *Confirmed.* Fix now.
- `src/worker/admin.test.ts:2262` (`swipe(now - 3_600_000, …)`) and `:2345` (`now - 1_000`) use the real clock. `admin.test.ts` has no `useFakeTimers` or `setSystemTime` at all.
- Between 00:00 and 01:00 Brussels, the swipe falls on yesterday and `body.tournee` is null. `src/worker/sync.test.ts:1636-1645` has the same 60-second window.
- CI runs at that hour: PR #521 merged at 23:26 UTC (01:26 Brussels).
- **Lesson:** a test about "today" fixes the clock, as `dashboard.test.ts` and the recap tests already do.

**F11. The door-day rule has three implementations, and the tie-break is tested on one.** Duplication map. Defer (action 4).
- `src/worker/door-days.ts:36-72` (SQL windows, dashboard), `:77-135` (`doorDaysOn`, partitioned by prospect only) and `:140-300` (feed, JS day via `brusselsDays`). They share `LATEST_VISIT_FIRST` (`:19`). `src/worker/routes/status.ts:61` writes the same ordering by hand.
- The tie-break tests ("breaks a visited_at tie…") cover `doorDaysBetween` only (`dashboard.test.ts`). No test runs the three readers over one dataset.

**F12. No Worker test parses a response with its zod schema.** Defer (action 4).

**F13. The query-plan tests plan hand-copied SQL.** Defer (action 4).

- Only `doorDaysTouched` is planned from the real statement (`admin.test.ts:1740-1768`).

**F14. DST days are untested for `doorDaysOn`, `writeTournees` and `todayTournee`.** Defer (action 4).
- The clock-change tests reach only `doorDaysBetween` (dashboard) and `doorDaysTouched` (feed).
- Replacing `brusselsMidnightDaysFromNow(dayStart, 1)` with `dayStart + DAY_MS` would pass every test on a normal day.

**F17. The admin round re-derives `left`.** Defer.
- `src/worker/routes/admin.ts:188-192` filters on `stop.left || visitedIds.has(…) || !prospect`, with `openAssignedProspects` alongside. The epic Notes say `left` is derived in one function (`isStopLeft`, `src/shared/tournee.ts:27`).
- Removing `stop.left` fails no test. No test compares the admin round with the sync response for the same data.

**Unverified, lower weight (defer, or drop if the owner prefers):**

### Diff-scope review: client

The client adversarial and edge-case lenses never finished (Epic summary). These findings come from the client verification-gap lens and the Worker lenses' reads of the client seams.

**F9. « Nouveau » is lost when the phone clock runs ahead of the server.** *Confirmed in source, not run.* Defer to a story (action 3).
- A joiner gets `addedAt = body.serverTime` (`src/client/field/sync.ts:294`). The flag is `stop.addedAt > today.startedAt` (`src/client/field/tournee-stops.ts:267`).
- The server clamps `startedAt` to its own `now` (`src/worker/tournee.ts:40`), which is that response's `serverTime` (`routes/agent.ts:304`).
- So with the phone ahead, a joiner appended in the sync that first delivers the tournée gets `addedAt == startedAt`, and it is numbered but not marked. The same happens for joiners appended while the swipe is unsent, because the local `startedAt` is the phone's clock.
- Every joiner test uses a `startedAt` safely earlier than `serverTime`.

**F15. Client tests that do not pin what they claim.** Defer (action 4). The first is an invariant-5 stake.
1. "Deleted only on `accepted`" has no partial case: a sent stop the server did not list, next to one it did (`sync.ts:268-273`). A change to "delete everything sent" passes every test.
2. A stop carrying its own `unconfirmed` stamp is never shown to be held back (`sync.ts:158-163`). `sync.test.ts:897` makes only the tournée unconfirmed.
3. The "counter does not move" assertions can resolve on an intermediate render (`TodayScreen.test.tsx:334-352`), or skip the rendered counter (`CarnetScreen.test.tsx:278-330`).
4. The "after a cache wipe + sync" tests never wipe or sync (`TodayScreen.test.tsx:354`, `CarnetScreen.test.tsx:254`).
5. The midnight test does not assert that the save lands before the start screen (`App.test.tsx:529-557`).
6. The real `RoundMap` glyph is tested only where the position equals the number (`RoundMap.test.tsx`).
