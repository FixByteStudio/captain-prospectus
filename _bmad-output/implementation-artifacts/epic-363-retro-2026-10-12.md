- **Disposition.** This instance: **accept**, the check is now made and recorded below. Upstream: actions 5 and 6.

#### F2: on Fichier & colonnes a long hint runs over the column select, and the phone blocks are clipped (medium at phone width, epic-owned, #368)

- **Evidence.** `TableCell` is `whitespace-nowrap` (`src/client/ui/table.tsx:71`) and the hint is a `max-w-xs` block inside it (`ColumnsStep.tsx:191-193`), so the text does not wrap. Measured on the local build with the Identifiant source hint:
  - 1280px: the text is 525px wide in a 320px box and ends at x = 844; the Select starts at x = 699. The hint is drawn across the Select for 145px.
  - 390px: the hint is cut at the panel edge (« …un nom corrigé m »), and every Select ends at x = 391 while the panel ends at x = 374, so each trigger loses its right edge and chevron.
- **Why the tests pass.** `ColumnsStep.test.tsx` asserts chips and counters; a DOM without layout cannot see an overflow. The spec says "Not checked in a browser against the mockup".
- **Disposition.** **Fix now**, small (action 1).

#### F3: a map import can report a CSV file's rejected lines (medium, epic-owned, seam between #367 and the result dialog)

- **What happens.** Pick a CSV with rejected lines, press Retour on Fichier & colonnes, then « Dessiner une zone » and import. The dialog reads « 0 prospects créés · 2 prospects mis à jour · 4 lignes rejetées »: the 4 are the CSV's. The import log for the same run was sent `rejected: 0`, so the dialog and Derniers imports disagree.
- **Evidence.** Observed on the local build. `ImportScreen.tsx:142` returns to Source without clearing `parsed`; `chooseMap` (`:93-96`) sets only the fork and the step; `ResultDialog` always takes `rejected.length` (`:173`), which is derived from `parsed`.
- **Why the process missed it.** Before #367 a file was chosen on its own step after the fork, so Source could not be reached with a file loaded. #367 moved the file read to Source and made Retour on step 2 go there; it ran with no review lens. The review bot raised exactly this on PR #380 three minutes before the merge (`ImportScreen.tsx:92`), and nobody answered it (F6).
- **Same lines, by reading only.** `onParsed` (`ImportScreen.tsx:72-78`) never sets the fork back to `"csv"`. A file read that finishes after « Dessiner une zone » would land on Fichier & colonnes with the fork still on the map, and the CSV rows would be stamped `osm`. Not reproduced; the window is one file read. Also from the bot on PR #380.
- **Related.** On the map path the log counts unnamed places as rejected (`MapStep.tsx:340`) and the dialog never mentions them, so « 1 rejeté » in Derniers imports has no counterpart in the dialog.
- **Disposition.** **Fix now** (action 2).
