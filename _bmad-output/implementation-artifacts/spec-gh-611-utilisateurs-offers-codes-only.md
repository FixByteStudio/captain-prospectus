## Intent

**Problem:** Since 3.2 (#610) no form accepts a passphrase, yet Utilisateurs still offers « Nouvelle phrase de passe », the Worker still issues one and `users.passphrase_hash` still stores it (ADR-0038 decision 1, R9).

**Approach:** Remove the passphrase end to end — route, schema, generator, query hook, dialog, row-menu item, deactivate branch, copy, tests — and drop `users.passphrase_hash` in one migration.

## Boundaries & Constraints

**Always:** one new migration in `drizzle/`, generated by `pnpm db:generate` from `schema.ts`, reviewed by `migration-guard`; French only in `src/client/copy/admin.ts`; `CodeDialog` and `UsersScreen`'s issued state stay as they are; `grep -ri passphrase src` finds nothing; `CLIENT_VERSION` does not move (not the sync contract).

**Never:** hand-edit or squash an existing migration; change the code's format, lifetime or normaliser, or the login route; edit accepted ADR bodies (ADR-0029, ADR-0038 keep their history); touch `.dev.vars`; add any line to the code dialog.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Admin's code | Administrateurs tab → own row or another admin → Générer un code | Code dialog as today | — |
| Admin's code on the agent form | `{kind: code}` with an admin's code | same 401 as a wrong code, code unspent (3.2, unchanged) | same 401 body |
| Row menu | any row, desktop or phone | Générer un code, then Désactiver; no passphrase item | — |
| Old route | `POST /api/admin/me/passphrase` | 404 (no route) | — |
| Deactivate | PATCH `{active:false}` | sessions and codes deleted as today; no column to clear | last-admin 409 unchanged |

**Decisions (owner, 2026-10-22):**
- No admin line in the code dialog: an admin who types their code on the agent form gets the same refusal as an agent with a wrong code. R11's dialog line is dropped; the issued state carries no role.
