## Findings

### F1: Done-when 4's "every admin-only module" is enforced for npm packages only
*Aggregate view: spec-to-implementation reconciliation. Disposition: **defer**, file an issue.*

`check-precache.mjs` fails only when a precached chunk holds a package on its `ADMIN_ONLY` list
([check-precache.mjs:54-67](scripts/check-precache.mjs#L54-L67)). The module map records
first-party source as repo-relative paths
([chunk-module-name.ts:15-17](scripts/chunk-module-name.ts#L15-L17)), but nothing checks them. So
`DashboardScreen.tsx`, `VisitsChart.tsx` or any other `src/client/admin/**` module imported from
the field entry would ship to phones and CI would pass.

The narrowing was a deliberate decision and it is on the record. `spec-gh-105:100` says *"Why
packages, not `src/client/admin/**`. The field entry chunk already legitimately holds
`src/client/admin/status.ts`, so a path rule would fail today."* The review rejected the finding
as out of intent (`spec-gh-105:87`). The epic's Done-when 4 was never reworded to match, so the
spec and the contract still disagree.

The blocker is a misfiled module. `admin/status.ts` is shared with the field, because `StopRow`
imports it. #116 hit the same wall: it had to put `STATUS_FILL` in `admin/dashboard/status-fill.ts`
because *"the first build with it in `status.ts` put the map in the field entry chunk"*
(`spec-gh-116`, Implementation Notes).

**What would prevent the next one:** move the shared parts of `admin/status.ts` out of `admin/`,
then add a `src/client/admin/**` path rule to the guard. After that the directory name is the
contract.

### F2: Every dashboard story grew the field precache with admin strings, against Done-when 4
*Aggregate view: architecture delta. Disposition: **defer** to #20 and raise its priority. The
spec wording needs reconciling.*

Done-when 4 reads *"the field precache changes only by #93's fix"*. The stories' own before/after
quotes show it changed with most of them:

| Story | Precache | Cause (spec) |
|---|---|---|
| #107 | 676.74 → 680.91 KiB | "+0.86 KiB entry JS from shared/copy/format, +3.3 KiB shared Tailwind CSS" (`spec-gh-107:89`) |
| #109 | +0.24 KiB | "all in the entry chunk … from the copy strings and formatters" (`spec-gh-109:90`) |
| #110 | +4.57 KiB | "CSS +3.91 KiB … entry +0.40 KiB copy/formatters, schemas +0.26 KiB" (`spec-gh-110:93`) |
| #111 | +0.52 KiB | schemas and CSS (`spec-gh-111:90,94`) |
| #113 | +1.78 KiB | "CSS +1.27, `schemas-*` +0.52" (`spec-gh-113:90`) |

That is at least **11.28 KiB** across five quoted deltas. #112 and #114 quoted totals but not
deltas.

The built output confirms the cause. "Dernières visites", "Pipeline par statut", "Activité par
agent", "Visites dans le temps" and "vs période précédente" are all in the precached
`constants-*.js` chunk (68.91 KiB), not in `AdminApp-*.js`. `copy.ts` is one `as const` object, so
it cannot be tree-shaken. That is issue **#20**, open since before this epic. `copy.ts` grew from
650 to 820 lines over the epic and is 953 lines today. Tailwind's single stylesheet has the same
problem for admin-only classes.

`dashboardResponseSchema` itself stays out: it appears only in `AdminApp-*.js`.

**Why it matters now:** `main` measures **939.26 KiB of 1,000**, 25 entries. That leaves 60.74 KiB
of headroom, down from 322.91 KiB at epic #59's close. The additional ~66 KiB of precached icons
that the ceiling does not count (#88) put the real install at roughly **1,005 KiB**. Most of the
rise is epic #117's lazy map chunk and epic #174, not this epic, but this epic's share is the part
Done-when 4 ruled out.

**What would prevent the next one:** a Done-when that a shared module makes impossible should be
caught when the epic is broken into stories. Every PR quoted its growth honestly, but no one
reported the clause as unmeetable.

### F3: `routes/admin.ts` has grown into a 1,746-line file, with the dashboard as its largest section
*Aggregate view: god-class growth. Disposition: **defer**, as a proposal for the owner.*

`admin.ts` grew from 1,278 lines at `0721a71` to 1,648 at `a9480b1` (+370 net, the epic's
fourth-largest churn). It is 1,746 lines today, after #177 extended G1 again. The dashboard block
alone, [admin.ts:204-587](src/worker/routes/admin.ts#L204-L587), is about 385 lines: one handler,
five SQL helpers, two fragments and the day-index builder. It shares the file with 18 other
routes. Its tests already live in their own file (`src/worker/dashboard.test.ts`, 1,029 lines).

This is not a defect today. The code is well commented and #116 already de-duplicated the SQL
fragments. It is the file that each dashboard and admin story extends, though, and the epic noted
that *"the admin lane is sequential because its entries share `admin.ts`"* (epic #104,
Decision 2026-09-25). Extracting the dashboard's queries into `src/worker/dashboard.ts`, with the
route left in `admin.ts`, would let later stories touching the dashboard and other admin routes
run in parallel.

### F4: The deferral rule fired on this epic and nothing was scheduled
*Process lesson. Disposition: **fix now**.*

CLAUDE.md:23, adopted from epic #59's retro (action 7), says *"A deferral repeated across two
stories with the same reason schedules the enabler story instead of a third deferral."* Two
stories in this epic deferred the same verification for the same reason:

- `spec-gh-110:109`: *"The tooltip header, legend order and tick format are wired but untested;
  Recharts draws nothing at happy-dom's 0 width."*
- `spec-gh-111:109`: *"No client test observes which series each sparkline draws, because

The cost is on the record. `deferred-work.md` says *"Swapping `data.visits.byDay` and

**What would prevent the next one:** the rule exists, but nothing checks it. The close pass on an
epic should group `deferred-work.md` by reason, as well as by `source_spec`.

### F8: The CPU budget is met with less than 2 ms of cold headroom, and nothing enforces it
*Verification gap. Disposition: **accept as-is**, recorded so later retros stop re-flagging it,
with an open question.*

Done-when 2 is met, and measured more carefully than the spec asked. #113 replaced the inspector
approach (which reported ~28 ms of mis-booked D1 waits) with `scripts/measure-dashboard-cpu.mjs`.
That script runs the bundled Worker in Node's V8 against a copy of the seed, with SQLite's own CPU
taken out. Warm requests take 0.42–0.53 ms (median). A cold first request takes **7.9–8.2 ms, with
9.9 ms seen once** (`docs/free-tier-budget.md:59-68`). After #177 added three figures, the same
file records *"the headroom is under 2 ms: the next figure added to G1 should be measured the same
way … and may need its own endpoint"* (`:69-75`).

`EXPLAIN QUERY PLAN` pins `visits_visited_idx` in a worker test (`spec-gh-106`), and migration
`0006` is additive: a single `CREATE INDEX`. The gap is the one #113 deferred: no automated CPU
check exists, because it needs seeded local D1 and hardware timing. The doc's re-measure
instruction is the only control.
