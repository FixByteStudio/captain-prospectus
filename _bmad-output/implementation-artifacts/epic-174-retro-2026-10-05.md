### F1: Done when 2, the epic's main quality gate, was never run (high, verification)

- **What the record shows.** The story that signs off CAP-3's responsive and theming rows is `hitl`. The owner's checklist was prepared (`01029d8`) with every row's DOM-test pin listed, and **278 of 278 boxes are unticked**. The owner decided on 2026-09-28 that it waits on #209 (#185 comment). #209 still shows the session-expired dialog and the offline-after-reload page as "specified but not built". Only the banner shipped (`28339a7`).
- **Why it matters.** The epic's own inception notes explain that the DOM harness is happy-dom, which "evaluates neither media queries nor computed colour", and that epic-shared-shell closed "with this same clause unverified (retro F6)". This is the same clause, unverified again, for the same reason.
- **Disposition.** Fix now: run the checklist. Ask the owner whether it still waits on all of #209. Upstream lesson: a human check that waits on an unbuilt feature should not be the *last* story; see action item 2.

### F2: at tablet width the Prospects table scrolls sideways and hides the row menu (medium, behaviour)

- **Observed.** At 820 px (sidebar collapsed), `/admin/prospects` renders an 861 px table inside a 723 px `overflow-x-auto` container. The "Dernière visite" column is cut off, and the row menu (`⋯`), the only per-row way to assign or change a status, is out of view until the admin scrolls the table sideways. I confirmed this with `scrollWidth` and a screenshot. At 1280 and 390 px nothing overflows (390 px is the list layout).
- **Contradicts.** EXPERIENCE.md Table pagination row (`:137`): "tables never get a scroll area of their own". The vendored `ui/table.tsx:6` wraps every table in `overflow-x-auto`.
- **Why the process missed it.** The checklist rows for this are all "owner, on device" (F1), and the DOM tests cannot see layout.
- **Disposition.** Fix now: the table needs to fit at 768 to 1023 px (hide the Adresse column below 1024 px, or move the row menu to the first column). A decision for the owner, then a small story. Also quoted for #185's sign-off.

### F3: name search is accent-sensitive in a French dataset (medium, behaviour, known)

- **Observed.** `?q=café` finds 21 places; `?q=cafe` and `?q=CAFÉ` find 0. SQLite `LIKE` folds ASCII only.
- **Record.** Deferred in #176's review (`deferred-work.md`, "Prospect name search folds ASCII only", issue #188, open). It is real in daily use: a Brussels base is full of "Café", "Crêperie", "Salon de thé".
- **Disposition.** Defer is no longer enough: Done when 3 says search "returns results that match D1", and an admin who types without accents gets no results. Schedule #188 (action item 3).

### F4: one deferral repeated across two stories with the same reason, and no enabler scheduled (medium, process)

- **What happened.** The CSV and map import paths both deferred the same item as "pre-existing": the server's `ApiError` message (400/403/426) is dropped and the Alert invites a retry that cannot work (#180 row 12, #181 row 14). It is still open in `deferred-work.md`. Two related items are open beside it: a failure Alert stays stale when the admin switches provider or searches again on the map path (#181 row 15), and in-app navigation during a running import drops the `beforeunload` guard while batches keep sending (#180 row 13).
- **The rule.** CLAUDE.md: "A deferral repeated across two stories with the same reason schedules the enabler story instead of a third deferral". The sweep (#186) took five other items and not these.
- **Why it matters.** Import is the admin's bulk writer. The "page can't be left mid-import" rule is in the spine; today a sidebar click leaves the screen and the batches keep sending with no result dialog.
- **Disposition.** Defer with a scheduled enabler: one small story "Import failures say why and survive navigation" (action item 4).
