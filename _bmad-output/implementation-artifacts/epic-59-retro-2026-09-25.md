## Findings

### F1 — The band header is written out four times in `App.tsx`, and the closing sweep added the fourth
*Aggregate view: duplication map. Disposition: **fix now**.*

`<header className="safe-top bg-band text-band-foreground"><div className="flex h-band-height
items-center gap-3 px-4">…` appears verbatim at
[App.tsx:117](src/client/App.tsx#L117), [:198](src/client/App.tsx#L198),
[:292](src/client/App.tsx#L292) and [:308](src/client/App.tsx#L308) — the field frame, the
admin-chunk fallback, the identity-error state and the loading state.

Blame splits it across the boundary: `5bf0367d` (#65, PR #77) created three, and `8c2a1cd8`
(#67, PR #89) added the fourth — the sweep whose stated job was to close the epic's gaps. Its own
comment names the duplication it was creating: *"Same band-plus-`<main>` shape as the error state
above"* ([App.tsx:303](src/client/App.tsx#L303)).

`src/client/Band.tsx` already exists as the home for shared band pieces, and already exports
`BandBrand` for precisely this reason.

**What would prevent the next one:** the sweep's four lenses (blind-hunter, edge-case,
verification-gap, intent-alignment) hunt defects, not repetition. Aggregate duplication is
invisible to them by construction — it is only a defect when you see all four sites at once.

### F2 — `spec-gh-67`'s recorded baseline is one merge behind the branch it was built on
*Aggregate view: spec-to-implementation reconciliation. Disposition: **fix now**.*

`spec-gh-67-refactor-sweep.md:6` records `baseline_commit: 'fc2d4cda39ae…'`. The sweep's first
implementation commit `8c2a1cd` has parent `6bcc5a0` — the #84 harness merge — and PR #89 states
it plainly: *"all green from a clean build, on top of `6bcc5a0`."*

The gap is exactly one merge, but it is the merge that brought in #83's 1,300-line test harness.
Any stories-mode tool deriving #67's diff from its frontmatter attributes that harness to the sweep.

**What would prevent the next one:** `baseline_commit` is stamped when the spec is drafted, not
when the branch is cut. Epic #59's own 2026-09-25 decision made #67 *wait* on #83, so a stale
baseline was guaranteed the moment that decision was taken. Stamp the baseline at branch time, or
re-stamp it at PR time.

### F4 — The same deferral was written five times before it became a story
*Process lesson. Disposition: instance **accepted** (it was closed, and well); process **fix now**.*

Five story specs deferred the same thing for the same reason, near-verbatim: *"the repo has no DOM
test harness … adding one is a new dependency that needs its own justification"* — `spec-gh-61`,
`spec-gh-63`, `spec-gh-64`, `spec-gh-65`, `spec-gh-66` (`deferred-work.md`, entries 2, 7, 11, 12,

*"entry 9 (#83) adds a DOM test harness for the shell before the refactor sweep … It closes the
verification gap the GH #61 review deferred."*

The cost is on the record. #66's deferral: *"Verified by deletion during review (441/441 still

branch (PR #89 › Review). Stories #61–#66 all shipped hand-verified.

**What would prevent the next one:** a deferral repeated across two stories with the same reason is
a signal to schedule the enabler, not to write it a third time. The trigger is cheap to check —
`deferred-work.md` already groups by `source_spec`.

### F5 — `isCurrent` and `isCurrentTab` implement the same rule twice, and should stay that way
*Aggregate view: duplication map. Disposition: **accept as-is** — recorded so later retros stop re-flagging it.*

[admin/nav.ts:65-67](src/client/admin/nav.ts#L65-L67) and
[field/tabs.ts:70-73](src/client/field/tabs.ts#L70-L73) both spell out
``pathname === path || pathname.startsWith(`${path}/`)``. Two stories built them
(#63 and #66), from different baselines.

This is the right call and the code says so: `tabs.ts` names the admin function in its comment and
explains the one deliberate difference (`/tournee` is an index route and must match only itself).
Sharing the helper would import an `admin/` module from the entry chunk and hoist it out of the
lazy admin chunk — against ADR-0019 and ADR-0026. The duplication is forced by the chunk boundary.

   66 KiB a phone genuinely downloads on install. Changing the basis is an ADR decision and it moves
   the number every later PR quotes. Today's 322.91 KiB of headroom makes it non-urgent; epic 2's
   Recharts payload may not.
2. **Is the admin-chunk guard worth a real assertion?** (F3 caveat.) A per-chunk symbol assertion
   over `dist/client/assets/` would be cheap and would close it exactly; the alternative is
   accepting that the ceiling catches only gross leaks.
3. **How should Done-when 3 and 4 be discharged?** A browser-driven check is a real dependency
   decision for this repo; an owner walkthrough at the three widths is not, and would close it now.
4. **Was there a session-log gap worth fixing?** Only #71 left `wt-pr71-log.md` /
   `wt-pr71-review.md`. Eight other stories left none, so no process lesson in this retro is drawn
   from what a session actually tried and abandoned — only from what the specs and PRs recorded
